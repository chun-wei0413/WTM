## 這個檢索在做什麼

檢索是**文字對文字**。圖片進來時,視覺模型先寫下它的文字描述(意思、使用情境、標籤、圖中文字),描述被建成兩種索引(向量、關鍵字)。使用者輸入的查詢文字去比對這些描述,找到後回傳該描述所屬的圖。

所以準確度由兩件事相乘:**描述寫得好不好**,和**文字檢索做得好不好**。這份評測量的是整條鏈。

## 怎麼評測

沿用資訊檢索的標準做法(測試集評測,見文末文獻):固定文件集、一批查詢、每題的正確答案,再算指標。

| 項目 | 做法 |
|---|---|
| 正確答案 | 二元;同一個梗在圖庫裡有多個條目時,每個都算對(例如 Drake 有 3 個) |
| 指標 | S@k:前 k 名內有正確答案的題目比例;MRR@10:第一個正確答案名次的倒數平均;nDCG@10 |
| 不確定性 | 對題目重抽樣 4,000 次,算 95% 信賴區間 |
| 比較兩個系統 | 同一批題目做配對檢定(配對自助法加隨機化檢定) |
| 避免自己考自己 | 題目不從圖庫自己的描述抄;調參數只用一半題目,另一半驗證,隨機拆 200 次 |
| 忠實度 | 離線比較程式重現應用程式的搜尋,187 題前 10 名與正在執行的系統完全相同 |

| 題組 | 題數 | 來源 | 偏差 |

## 混合權重為什麼是 0.7

這個權重(語意 0.7、關鍵字 0.3,各自先縮放到 0 到 1 再相加)被問到時,答案要有數據。做法:在三組題目上把權重從 0.0(只用關鍵字)掃到 1.0(只用語意),
**在作者題 A 選,在 B、C 驗證**,然後問「0.7 與別的權重,在同一批題目上,差別是不是大到不是運氣」。重跑只需讀已存的結果,不必連資料庫:
`python scripts/eval-alpha.py`(結果檔 `eval/results/compare-*.json`)。

|---|---|---|---|

| 1.0(只用語意) | −0.019 [−0.029, −0.010] | < 0.001 | 較差 |

老實的結論:

- **0.7 不是尖銳的最佳點**。0.5、0.6、0.7 在統計上分不出來(差 0.000 到 0.004,遠小於誤差);我選 0.7 是因為它在三組題目上的數字都是最高,而且 0.8 以上已經量得到略差。證據不足以主張它比 0.6 或 0.5 好。
- **往關鍵字傾斜是明確的錯**:語意權重 0.4 以下(也就是關鍵字比現在更重)全都明顯較差。
- **與只用語意比**:MRR 好 0.019(p < 0.001)、前 10 名好 0.019(p = 0.04);第 1 名好 0.013,**不顯著**(p = 0.09)。留存題 C 單獨看,MRR +0.014(p = 0.08)、前 10 名 +0.030(p = 0.12),**也不顯著**;只有三組合併才顯著。所以關鍵字通道帶來的準確度提升很小(約 1 到 2 個百分點),主要發生在「前 10 名有沒有」與排序;它更大的價值是向量服務掛掉時的備援(第 1 名 49% 提升到 73%)。

### 這個結論的前提與限制

- 三組題目用的是同一個圖庫、同一個嵌入模型、同一種關鍵字斷詞(相鄰兩字)。換任何一個,最高點都可能移動,要重跑。
- 權重是對「各自縮放到 0 到 1」之後的分數;縮放方式不同(例如不用 min-max),0.7 就不能直接搬過去。
- C 只有 134 題、涵蓋 67 個梗,95% 區間約 ±6 個百分點;B 的絕對數字很低(很多題沒有唯一答案),只用來看曲線的形狀。
- 作者題 A 是我寫的、而且當初就是用它選權重的,所以 A 上 0.7 最高是意料中事;能支持這個選擇的是 B 與 C。

## 圖庫擴大到 1,305 張之後(2026-10-19)

圖庫從 410 張擴到 1,305 張(新增來源:memes.tw、Imgflip 熱門模板;描述由 Claude 逐張看圖寫成,部分由 Gemini 寫成)。嵌入模型、斷詞、權重都沒變,只有圖庫變大;三組題目重跑(圖庫擴大前的結果存在 `eval/results/before-1305/`)。

### 第一步:原封不動重跑,發現標答跟不上圖庫

在實際執行的應用程式上重跑基準(`baseline.json`,作者題 A 的 237 題):第 1 名 59%、前 3 名 82%、前 10 名 92%、MRR 0.710,與離線比較的數字一致。但 237 題裡 97 題第 1 名不是標答,**其中 78 題的第 1 名是新加入的梗**,而且很多其實是對的:問「派大星」,排第一的是新增的 Patrick 圖,標答卻只列舊的 4 個名字;問「女人對著貓大吼」,新增了同一個梗的另一張圖。原本的標答只認得 410 張裡的名字,所以這個數字低估了。

### 第二步:重標 A 的標答(只加不減)

對 A 裡的 75 題,在標答清單**加上** 144 個新圖庫裡的名字,原本的標答一個都沒改。規則:
- 新圖是**同一個梗**(例如 `Woman Yelling at a Cat`、`Two Buttons Original Four Panels`、`Gru's Plan Five Panels`),就算對。
- 查詢**本身就是在點某個角色或作品**(「派大星」「魷魚遊戲」「蜘蛛人」「蝙蝠俠」「六人行」等),那個角色或作品的新圖都算對。
- 只是「情境相近」「氣氛像」不算。看起來像但我沒看過圖的名稱(例如 `大小柴犬反`)沒加。
- 做法與限制:判斷是我看名稱、再參考描述做的,沒有第二個人複核,所以偏寬鬆的可能性存在(實體題尤其)。B 與 C 沒有重標,數字維持第一步的結果。

### 讀法(老實版)

- **準確度比 410 張時低一些,但沒有第一步看起來那麼慘**:A 的 MRR 掉 0.05(0.874 → 0.827),第 1 名掉 7 個百分點(83% → 76%),前 10 名只掉 2 個百分點(95% → 93%)。剩下的下降是真的:圖庫變 3 倍,相似的梗變多,正確的那一張排第 1 比較難。B、C 還沒重標,下降的幅度有多少是標答造成的,我沒有量。
- **0.7 仍在平坦區間,但已不是「三組都最高」**:A 上 0.5 到 1.0 彼此分不出差別(與 0.7 的配對差在 −0.008 到 +0.002,p ≥ 0.26);0.4 以下仍明確較差(關鍵字比現在更重就是錯,A 上差 0.046 以上,p ≤ 0.001)。A 上最高是 0.8,B 上是 0.7,C 上是 0.8。所以之前「0.7 在三組都是最高點」這句話,**在新圖庫上不成立**,能說的只有「0.7 落在不差的區間、不需要改」。
- **關鍵字通道的增益幾乎消失**:三組合併,0.7 對只用語意,MRR +0.002(p = 0.68),第 1 名 −0.009(不顯著),只有前 10 名 +0.023(p = 0.002)。重標後的 A 單看,0.7 比只用語意 MRR +0.008(p = 0.24),也不顯著。混合在新圖庫上主要是讓「正確答案進前 10 名」多一點,排序本身沒有更好。關鍵字通道留著的理由,剩下向量服務掛掉時的備援(這一點沒有在新圖庫重測)。
- 舊文件說「0.8 以上略差」,在新圖庫上不成立(0.8 與 0.7 差不到 0.003,不顯著)。

### 這次沒有做的事

- 向量服務掛掉時的備援沒有重測。
- B、C 沒有重標;也沒有針對新增的梗另外寫題目。新增的 895 張在題目裡幾乎只靠「重標」這個方式出現,所以這次量到的主要是「舊題目在更大的圖庫裡變多難」,不是新圖本身的搜尋品質。要量新圖,需要新題組(類似 C 的做法:另一個模型只看名稱寫題)。

### 其他

- **負向題**:8 題與梗圖無關的問題,搜尋一律回傳最接近的幾張,沒有任何一題被拒絕。改前用 RRF 分數設門檻救不了(門檻 0.025 擋掉全部負向題,也擋掉 41% 的正確第 1 名);改後分數落在 0 到 1,稍有分辨力,見「已做與建議」第 3 點。

## 已做與建議

已做:**關鍵字通道換成 BM25(中文用二字詞),用凸性組合融合**(語意權重 0.7,`wtm.search.dense-weight` 可調)。上面的「改前改後」表是它在應用程式上的實測。

還沒做,依值得程度:

1. **重新排序**:對前 20 名再排一次。空間最大(約 13 點)。
2. **補強「外觀」類的描述**:這類查詢最弱。
3. **「找不到合適的梗」的提示**:新的分數有一點分辨力(門檻 0.75 擋下 8 題無關問題中的 6 題,代價是 5% 的正確第 1 名),但只有 8 題無關問題,太少,不足以採用。

## 限制

- 題目都不是真實使用者的查詢(A 是我寫的、B 是本機模型寫的、C 是另一個模型寫的);真實查詢紀錄只有 23 筆。
- 人工判斷只有一位評審,而且沒有盲化。建議找人獨立標一批,算評審者一致性。
- 圖庫描述由 Gemini 寫,描述裡的錯誤(例如寫錯人名)沒有納入量測。
- 圖庫沒有台灣在地的梗,所以沒有量到。
- 只是一次量測;換圖庫、模型或描述,數字都會變。

## 文獻

以下研究的對象是文字段落檢索,正好是這個系統做的事。但這裡的「文件」是模型寫的短描述、語言是中文,這兩個條件文獻沒有涵蓋,所以以上結果都以自己的量測為準。

| 文獻 | 與本系統的關係 |
|---|---|
| Karpukhin 等,[Dense Passage Retrieval](https://arxiv.org/abs/2004.04906),EMNLP 2020 | 向量檢索在問答任務的前 20 名準確率比 BM25 高 9 到 19 個百分點 |
| Thakur 等,[BEIR](https://arxiv.org/abs/2104.08663),NeurIPS 2021 | BM25 是穩固的基準線,向量模型在沒見過的領域常常表現不佳 |
| Cormack、Clarke、Büttcher,[Reciprocal rank fusion](https://doi.org/10.1145/1571941.1572114),SIGIR 2009 | 本系統使用的融合方法(k = 60) |
| Bruch、Gai、Ingber,[An Analysis of Fusion Functions for Hybrid Retrieval](https://arxiv.org/abs/2210.11934),2022/2023 | 凸性組合通常勝過 RRF,而且 RRF 對參數敏感;與上面的實驗方向一致 |
| Chen 等,[M3-Embedding](https://arxiv.org/abs/2402.03216),2024(預印本) | 本系統使用的 `bge-m3`,支援 100 多種語言 |
| Sanderson,[Test Collection Based Evaluation of IR Systems](https://doi.org/10.1561/1500000009),2010 | 這份評測採用的做法 |

## 重跑

需要圖庫的兩個容器和 Ollama 在跑;第一個指令還要應用程式在跑,並用 `.env` 裡的管理員登入。

```bash
node scripts/eval-search.mjs --out eval/results/latest.json     # 對執行中的應用程式跑一遍(整條鏈)
python scripts/eval-compare.py eval/library-queries.json        # 比較各種排序方式(A,約 3 分鐘)
python scripts/eval-compare.py eval/library-queries-blind.json  # 盲測題(B)
python scripts/eval-compare.py eval/library-queries-heldout.json --json eval/results/compare-heldout.json   # 留存題(C)
python scripts/eval-alpha.py                                    # 權重曲線,讀已存的結果,不用資料庫或模型
```

|---|---|
